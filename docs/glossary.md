# CachePilot — Technical Decisions Glossary (Quick Reference)

A quick-scan index of technical decisions made throughout the
project. For full details on any decision, see `architecture.md`.

| Decision                                                                                                                            | One-line reason                                                                                                                                                                                                                                                 |
| ----------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Timestamp` as `int64` (Unix ms), not `time.Time`                                                                                   | JSON/pandas compatibility between Go and Python                                                                                                                                                                                                                 |
| `CacheStatus` as a distinct type (`type CacheStatus string`)                                                                        | discoverability/documentation, not full typo prevention                                                                                                                                                                                                         |
| `Source` (in `CacheDecision`) is a raw string, not a distinct type                                                                  | constructed in only two production places (the manager's fallback and the `mlclient` response conversion), low risk of inconsistency                                                                                                                            |
| `Hits/Misses/Evictions` counters use `atomic.Int64`, not `Mutex`                                                                    | independent counters, no need for multi-field coordination                                                                                                                                                                                                      |
| `internal/store` (not `internal/mongo`)                                                                                             | name collision with the official `mongo-driver` package                                                                                                                                                                                                         |
| Cache stores `value []byte` (not a typed struct)                                                                                    | full decoupling of the cache from the domain schema                                                                                                                                                                                                             |
| `config.yaml` + env var overrides                                                                                                   | reproducibility for experiment runs + deployment flexibility                                                                                                                                                                                                    |
| Logger: drop-on-full instead of blocking                                                                                            | keeps the critical path lightweight; a deliberate trade-off accepting partial data loss                                                                                                                                                                         |
| `log/slog` instead of manual `encoding/json`                                                                                        | standard library package, no new dependency, built-in log levels                                                                                                                                                                                                |
| Burst as a toggleable flag in the workload generator                                                                                | enables a direct comparison between stationary and bursty access patterns                                                                                                                                                                                       |
| `query_type` derived from the document itself (`media_size_kb`), not a synthetic label                                              | a natural, meaningful feature for ML, without manual injection                                                                                                                                                                                                  |
| ML model: offline training, inference-only at runtime                                                                               | keeps the critical path fast, reproducibility, explainability                                                                                                                                                                                                   |
| 5–10ms fallback timeout for gRPC                                                                                                    | prevents the main path from slowing down when the ML service is slow/unavailable                                                                                                                                                                                |
| `EnsureIndexes` called from inside `NewStore`, not from `main.go`                                                                   | the `posts` collection field is unexported; calling it where the collection is created avoided exposing internals just for this                                                                                                                                 |
| `run()` returns an error instead of `main()` calling `os.Exit` directly                                                             | `os.Exit` skips all deferred cleanup (logger flush, Mongo disconnect, gRPC close); returning an error keeps cleanup in the normal control flow                                                                                                                  |
| The access tracker is always constructed, regardless of cache policy                                                                | negligible cost when unused; keeps `main.go`'s wiring free of an extra conditional branch                                                                                                                                                                       |
| The ML gRPC client is only constructed when `cache.policy == "ml"`                                                                  | unlike the tracker, this dials a real connection — requiring it unconditionally would stop the lru/lfu baselines from starting without the ML service running                                                                                                   |
| Logger flushes on a 1-second ticker, not only on `Close()`                                                                          | data was previously only reaching disk on graceful shutdown; a crash (not just Ctrl+C) would have lost everything still buffered — periodic flush bounds that loss window to ~1s                                                                                |
| `config.yaml` relative paths resolve against the config file's own directory, not the process's cwd                                 | avoids a real bug hit during manual testing: `logging.path` resolved differently (and wrongly) depending on which directory `go run` was invoked from                                                                                                           |
| `workload-generator/config.py` is a Python dataclass + CLI flags, not a YAML file                                                   | unlike the long-running Go service, this is a run-once script re-invoked with different parameters per experiment; CLI flags make each run's exact settings self-documenting (the command line itself is the record) without editing a shared file between runs |
| `workload-generator` writes each run to its own timestamped folder and snapshots the Go service's log into it                       | fixed runs silently overwriting each other's results and manual `mv` steps being easy to forget                                                                                                                                                                 |
| Workload results now report avg/p50/p95/p99 latency, not just average                                                               | p95 latency is one of the project's stated evaluation metrics; average alone hides tail behavior                                                                                                                                                                |
| `requirements.txt` pins `protobuf` explicitly, (5.29.3; the committed stubs record 5.28.1 in their header)                          | the generated code checks the installed protobuf runtime at import time and raises `VersionError` on an incompatible version                                                                                                                                    |
| `LogEntry.Source` records what actually produced each response (`cache-hit`, policy name, or the decider's own source/fallback tag) | lets evaluation code measure how often "ml" policy decisions actually came from the ML service vs. fell back, not just overall hit rate                                                                                                                         |
| Admit model training tracks `auc` alongside `binary_logloss`, with early-stopping patience raised to 50 rounds                      | `binary_logloss` alone with low patience caused early stopping at iteration 1 on the imbalanced target, producing an undertrained model that never learned to predict the minority class                                                                        |
| Admit model's decision threshold is tuned on the validation set, not fixed at 0.5                                                   | for a heavily imbalanced target, the default 0.5 threshold is not necessarily where precision/recall trade off best for the minority class                                                                                                                      |
| Single-feature AUC is reported alongside full-model feature importance                                                              | cheap way to sanity-check whether each feature carries real signal on its own, before investing in feature engineering or selection work                                                                                                                        |
| TTL expiry removes the cached value, not only the deadline                                                                          | Removing just the deadline made expired entries look valid and turned them into hits.                                                                                                                                                                           |
| ML service refuses to start without a valid model                                                                                   | A silent fallback would mix deciders in "ml" results; Go already falls back to LRU.                                                                                                                                                                             |
| `decision_mode: heuristic` is an explicit mode, not a fallback                                                                      | Gives evaluation a clean baseline without contaminating "ml" runs.                                                                                                                                                                                              |
| Decision source is `model_name` from the metadata                                                                                   | Ties every logged decision to the exact model file.                                                                                                                                                                                                             |
| Single-request scoring is checked against batch scoring                                                                             | Category encoding or column order drift gives wrong scores without any error.                                                                                                                                                                                   |
| Raw logs are a JSONL file, not a database or message queue                                                                          | simple, human-readable, decouples the service from the training pipeline; durability and scale limits are accepted knowingly                                                                                                                                    |
| Posts are decoded into a BSON struct, then converted to a plain-typed JSON struct                                                   | marshaling a generic map silently emits Extended JSON (`$oid`, `$date`) for driver types                                                                                                                                                                        |
| `query_type` is computed once in the store read path                                                                                | every consumer reads the same value, with no lockstep updates across call sites                                                                                                                                                                                 |
| `Tracker.Observe` records and computes in one call, with fixed retention windows                                                    | prevents the silent recency-is-zero ordering bug and a retention shorter than five minutes                                                                                                                                                                      |
| `Manager` keeps its own TTL map and hit/miss counters                                                                               | the underlying cache has no TTL, so its counters would overstate the "ml" hit rate                                                                                                                                                                              |
| `Cache` has `Delete(key)` but no TTL parameter on `Put`                                                                             | keeps lru/lfu pure baselines; deletion is not counted as an eviction                                                                                                                                                                                            |
| The "ml" policy stores values in an LRU                                                                                             | the model only controls admission and TTL, so the measured variable is the admission layer                                                                                                                                                                      |
| `Decider.Decide` takes `key` separately from `Features`                                                                             | the key is for tracing only and is never a model input                                                                                                                                                                                                          |
| Burst candidates must be idle for `burst_min_idle_sec`                                                                              | a burst on an already hot key does not model a cold post going viral                                                                                                                                                                                            |
| `grpc_server.py` only translates; `inference.py` decides                                                                            | the decider can change by editing one file                                                                                                                                                                                                                      |
| The Go gRPC client is thin, plain and lazy-connect                                                                                  | an unreachable ML service surfaces on the first RPC and is handled by the fallback                                                                                                                                                                              |
| Wire-format conversion lives in `mlclient`                                                                                          | the `cache` package never imports the generated protobuf types                                                                                                                                                                                                  |
| `Manager` depends on a `PostFetcher` interface                                                                                      | the manager can be tested with a fake, without MongoDB                                                                                                                                                                                                          |
| `source` is written to the JSONL log on every record                                                                                | logs recorded before the fix cannot be used for the model-versus-fallback breakdown                                                                                                                                                                             |
| Offline features replay the log in time order and mirror `tracker.go`                                                               | training features must be computed exactly as the live tracker computes them                                                                                                                                                                                    |
| `payload_size_kb` is read from MongoDB, not the log's `response_size`                                                               | the model sees `media_size_kb` (0 for text posts); `response_size` is always above zero                                                                                                                                                                         |
| Look-ahead labels are a separate pass, and rows near the log end are dropped                                                        | keeps future values out of features; a missing next access near the end may only mean the recording stopped                                                                                                                                                     |
| Train/test and fit/validation splits are by time                                                                                    | a random split would train on rows that happen after some test rows                                                                                                                                                                                             |
| Time splits have no gap between parts (known limitation)                                                                            | late training labels can overlap the test period, so metrics may be slightly optimistic                                                                                                                                                                         |
| `scale_pos_weight` is computed from the fit set                                                                                     | counters the admit/reject imbalance (about 96/4) without hand-tuning                                                                                                                                                                                            |
| TTL is a flat five minutes in both decision modes                                                                                   | the model predicts admission only; the value is a starting point, not derived from data                                                                                                                                                                         |
| Zipf popularity uses explicit bounded weights, not `numpy.random.zipf`                                                              | the numpy rank is unbounded and can exceed the number of posts                                                                                                                                                                                                  |
| Request timing uses absolute monotonic scheduling                                                                                   | accumulated `sleep()` calls drift over a long run                                                                                                                                                                                                               |
| A burst takes a fixed share of traffic (`burst_share`), not a multiplier on the post's weight                                       | the weight multiplier added only about 1.5 requests per burst (0.18% of traffic); a share gives about 300 regardless of rank                                                                                                                                    |
| The request plan is built from the seed on simulated time (index / rate)                                                            | the same seed, config and post list give the same sequence, with no wall-clock dependence; `plan_sha256` checks it                                                                                                                                              |
| The plan is a pure function (`workload_plan.py`), separate from sending                                                             | a dry run and the tests need only numpy, no MongoDB, service or network packages                                                                                                                                                                                |
| Stationary requests and bursts use separate random streams                                                                          | with bursts off the sequence equals the earlier generator, and a burst run is the stationary run with some requests replaced                                                                                                                                    |
| `run_config.json` records `plan_sha256` and `post_ids_sha256`                                                                       | to notice a changed plan or a re-seeded database                                                                                                                                                                                                                |
| The service-log snapshot copies the whole appended file (known limitation)                                                          | runs that share one log file get overlapping snapshots, so each run needs its own log path                                                                                                                                                                      |
| `pipeline.py` chains the three data stages; each stage also runs alone                                                              | one stage can be re-run, for example with a different label window, without redoing the others                                                                                                                                                                  |
| Pipeline and training scripts default to working-directory-relative paths                                                           | they must be run from their own directories                                                                                                                                                                                                                     |
| One HTTP endpoint, `GET /get?key=`, with 400, 404 and 500                                                                           | point lookups only; keeps the benchmark surface small                                                                                                                                                                                                           |
| The service-log snapshot is copied before the log buffer is fully flushed (known limitation)                                        | the last few records are missing and the last line can be truncated; the live log is complete                                                                                                                                                                   |
| `Logger.Dropped()` is not reported anywhere (known limitation)                                                                      | a run that dropped records cannot be told apart from a clean one                                                                                                                                                                                                |
| Protobuf stubs for Go and Python are committed; the Python import is edited by hand to be relative                                  | nobody needs `protoc` to run the services; regenerating means repeating the edit                                                                                                                                                                                |
| Python dependencies are pinned only for the ML service (known gap)                                                                  | the pipeline, generator and seed script environments cannot be recreated from the repository                                                                                                                                                                    |
